01

Что это и общая архитектура

КопиМотик — клиентское одностраничное приложение (SPA) на React, упакованное в один самодостаточный HTML-файл. Приложение рендерится в <div id="root"> через ReactDOM.createRoot. Поверх готового React-бандла работает слой автономных плагинов-надстроек: они не трогают бандл, а читают и пишут данные через единый интерфейс хранилища window.storage.

Архитектура двухрежимная — одна и та же кодовая база работает либо целиком в браузере, либо с бэкендом:

        ┌──────────── Браузер (React SPA + плагины) ────────────┐
        │   window.storage.get / set / delete / list            │
        └───────────────┬───────────────────────┬───────────────┘
                        │                        │
          режим A: localStorage      режим B: REST → Node (server.js)
          (статика, без сервера)     /api/kv → db_adapter.js → SQLite

Ключевая инженерная идея: хранилище абстрагировано за window.storage, поэтому фронтенд не знает, лежат данные в localStorage или в SQLite на сервере — реализацию подменяет один из скрипт-шимов.

02

Технологический стек

  • React 18.3.1 + ReactDOM (createRoot)
  • Vanilla JavaScript — плагины-надстройки и шимы хранилища
  • Node.js ≥ 22.5 — бэкенд server.js на встроенном node:http
  • SQLite через встроенный node:sqlite (DatabaseSync), опционально better-sqlite3
  • SQL — схема schema.sql
  • SVG — вся графика (маскот, шкалы, косметика) рисуется вручную, без графических библиотек
  • Anthropic Messages API (claude-sonnet-4-20250514) — AI-коуч, с локальным фолбэком
  • Сборка фронтенда — esbuild-бандл, минифицированный, инлайн в HTML
У серверной части нет зависимостей времени выполнения — всё на стандартной библиотеке Node.

03

Состав index.html — 10 скрипт-блоков

В порядке загрузки внутри файла:

  1. DEMO SHIM — автономный режим: window.storage на in-memory + localStorage, засев демо-профиля.
  2. km_goals.js — слой «важности» целей: считает приоритет из суммы, накопленного, срока и свободного бюджета. Чистая надстройка, в данные ничего не пишет.
  3. km_moto.js — косметика «Мотоцикл»: SVG-группы в системе координат маскота (viewBox="0 0 200 200"), два слоя — за и перед бегемотиком.
  4. km_server_shim.js — реализация window.storage поверх REST (/api/kv); km:session всегда локально в браузере.
  5. STANDALONE DEMO — переопределяет window.storage обратно на localStorage, перехватывает window.fetch и гасит запросы к Anthropic, засевает демо-аккаунт с высоким индексом.
  6. km_debt.js — «Разбор долгов» + калькулятор досрочного погашения; карточка во вкладке «Светофор». Считает кредиты даже без указанного остатка.
  7. km_invest.js — «Изобилие»: при высоком индексе и собранной подушке будит «спящие» накопления. Арифметика в window.KmInvest.
  8. km_pace.js — «Темп целей»: реалистичность целей, сколько откладывать в месяц. Арифметика в window.KmPace.
  9. km_check.js — кнопка «🧾 Чек» (ввод траты текст/фото/голос) + раздел «Мои чеки». Монтируется прямо в DOM. Именно её плашка давала баг на вкладке «Мотик».
  10. React-бандл — само приложение (esbuild, ≈333 КБ из ≈516 КБ файла).

04

Слой хранения window.storage

Единый асинхронный интерфейс (все методы возвращают Promise): get(key), set(key,value), delete(key), list(prefix). Ключи:

km:sessionТекущий вход. Всегда локально в браузере — чтобы в серверном режиме один вход не перелогинивал остальных.
km:usersСписок аккаунтов. В серверном режиме общий, при записи мержится.
km:user:<логин>Весь стейт пользователя одним JSON-объектом.

Две взаимозаменяемые реализации: localStorage (статика) и REST-обёртка над /api/kv (сервер). Базы данных в браузере нет (sql.js/wasm не используется).

05

Бэкенд server.js

Чистый Node без внешних зависимостей. Эндпоинты:

GET /healthzСтатус + имя драйвера БД.
GET /api/kv?key=Чтение значения.
POST /api/kvЗапись {key,value} (тело до 5 МБ; ключ/значение строго строки).
DELETE /api/kv?key=Удаление; для пользовательского ключа — транзакционная чистка по всем таблицам.
GET /api/kv-list?prefix=Список ключей.
* (остальное)Статика из public/ с SPA-фолбэком на index.html и защитой от path traversal.

Драйвер БД выбирается автоматически: есть better-sqlite3 — он, иначе встроенный node:sqlite. На старте: PRAGMA journal_mode=WAL, foreign_keys=ON, идемпотентная схема (CREATE TABLE IF NOT EXISTS). Переменные окружения: PORT (3000), HOST (0.0.0.0), KM_DB (путь к файлу БД).

06

db_adapter.js — мост «состояние ↔ SQL»

Драйвер-агностичный (работает с любым, у кого есть prepare().get/all/run и exec). Две функции:

  • loadData(db, userId) — собирает плоское состояние приложения из всех таблиц в тот же объект data, что использует фронтенд (переименование колонок через SQL-алиасы: monthly_payment AS monthly и т.п.).
  • saveData(db, data, userId) — сохраняет одной транзакцией (BEGIN/COMMIT, при ошибке ROLLBACK): профиль через UPSERT, а коллекции (долги, цели, чек-ины, чеки, челленджи, уроки) — «удалить всё по user_id и вставить заново».

07

Схема базы данных

Реляционная, корректный мультиюзер: у коллекций составной PRIMARY KEY (user_id, id) и индексы по user_id.

financial_profilesДоход, обязательные траты, платежи по кредитам, накопления, стабильность дохода, импульсивность, разбивка быта, флаг онбординга.
debtsДолги: платёж, остаток, ставка.
goalsЦели: сумма, срок (мес.), накоплено, статус.
purchase_plansПланы покупок для «Светофора»: цена, тип оплаты, платёж, ставка, срок, активность.
user_progressXP, уровень, серии (в т.ч. «чистая» без импульсов).
user_cosmeticsПалитра, шапка, аксессуар маскота.
user_settingsНапоминания и UI-флаги.
checkinsЕжедневные чек-ины с метриками (балл, ПДН, свободный остаток, подушка).
user_lessonsОбучающие уроки.
user_challengesЧелленджи.
expensesЧеки/траты: сумма, заметка, категория, эмодзи, источник (text/photo/voice).
app_kvУниверсальное KV для непользовательских ключей (km:users и пр.) — весь стейт в одном .sqlite.

08

Модель мультиюзера

  • Имя пользователя → user_id как u_<имя> (demo → u_demo).
  • Сессия локальна у каждого посетителя; список аккаунтов общий и мержится при записи — одновременные регистрации не затирают друг друга.
  • Удаление аккаунта чистит все таблицы пользователя в одной транзакции.

09

Плагины и «переживание» ре-рендеров React

Плагины km_debt / km_invest / km_pace / km_check вживляют свой UI прямо в DOM-узел .km-page, который контролирует React. Чтобы элементы не «слетали» при перерисовке, используется периодический tick() (через setInterval): он сверяет активную вкладку и синхронизирует/удаляет вставленные узлы. Бизнес-арифметика вынесена в глобальные объекты (window.KmInvest, window.KmPace) и тестируется отдельно от UI.

10

Финансовый индекс (алгоритм)

Балл 0–100 (pl() в бандле, копия — km_invest.indexScore()), измеряет защищённость и безопасность долга:

  • Устойчивость (вес 70%) — денежный поток (доля свободных денег от дохода, максимум при профиците ≈25%) + запас прочности (на сколько месяцев обязательных трат хватит накоплений относительно цели 3/4/6 мес. по стабильности дохода). При высоком доходе подушка перестаёт быть обязательной — доход её замещает.
  • Безопасность долга (вес 30%) — ПДН (подъёмность платежей) и общая долговая нагрузка к годовому доходу (ощутимо после ≈2 годовых доходов).
  • Стабильность дохода и дисциплина трат — мягкие поправки, гаснут с ростом устойчивости. Если остаток по кредиту не указан, он оценивается по платежу (≈18 платежей).
Балл монотонен: рост дохода и накоплений его не понижает, рост трат и долга — не повышает. «Упитанность» маскота привязана к индексу (weight: Vo(score)).

11

AI-коуч и фолбэк

Советы запрашиваются у Anthropic Messages API (claude-sonnet-4-20250514) запросом POST https://api.anthropic.com/v1/messages. Важно:

  • Ключа в коде нет (заголовка x-api-key нет) — вызов рассчитан на среду, где ключ подставляется платформой.
  • В клиентской сборке (index.html) window.fetch перехватывается и запрос к Anthropic намеренно отклоняется → показывается встроенный локальный диагноз (детерминированный расчёт по индексу). Размещённый сайт работает полностью офлайн (кроме шрифтов Google Fonts).
  • Чтобы включить «живого» коуча на проде — нужен серверный прокси, добавляющий ключ (напрямую из браузера нельзя: ключ и CORS).

13

Зависимости и требования

  • Статический хостинг: ничего не нужно — любой веб-сервер, отдающий файлы. Единственная внешняя загрузка — шрифты Google Fonts по https (есть фолбэк на системные).
  • Серверный режим: только Node.js ≥ 22.5. better-sqlite3 опционален (скорость + убрать пометку «experimental»). База — один файл kopimotik.sqlite (WAL; бэкап = копия файла).

14

Безопасность

Это демонстрационное/дружеское приложение, не банковский уровень:

  • Пароли хешируются некриптостойким собственным алгоритмом и лежат в общем km:users.
  • В серверном режиме нет HTTPS и нет защиты от перебора; по умолчанию слушается вся сеть (0.0.0.0).
Рекомендации для прод/интернета: держать в доверенной LAN; для интернета — обратный прокси (nginx/Caddy) с HTTPS и доп. аутентификацией, либо туннель (Cloudflare Tunnel / Tailscale); HOST=127.0.0.1, чтобы не пускать сеть.

Плюсы текущей реализации: REST ограничивает тело 5 МБ, статика защищена от path traversal, запись идёт транзакциями.

16

Исправленный баг

Плашка «Мои чеки» мелькала вверху вкладки «Мотик». Причина: orphan-узел km_check находится вне дерева React; при переключении вкладок React репарентил его наверх .km-page, а следующий tick() убирал — отсюда «мелькание». Фикс: синхронное удаление узла в capture-фазе клика по вкладке — до того, как React перерисует страницу.
